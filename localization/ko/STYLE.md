# 메크커맨더 골드 한국어화 스타일 가이드 (출격 전 범위)

대상: MCX.EXE(MechCommander Gold / Desperate Measures)에서 임무 시작 전에 보이는 모든 텍스트입니다. 메인 메뉴, 불러오기/저장/환경 설정, 병참(메크 격납고, 조종사, 구매, 수리/재장비), 브리핑, 작전 카드, 임무 결과 화면이 여기에 들어갑니다. 원문은 `localization/en/` 아래에 있습니다.

**우선순위: `glossary.json` > 이 문서 > 번역자 판단.** 용어집에 있는 단어는 `ko` 그대로 씁니다(조사만 붙입니다). 용어집에 없는 고유명사를 찾으면 임의로 정하지 말고 리드에게 알려 주세요. 리드가 `glossary.json`과 `names_coverage.md`에 추가합니다. 용어집을 고친 다음에는 `python -I localization/ko/check_glossary.py`를 다시 실행합니다.

> **사용자 결정 사항 (2026-10-19, 최우선):** Mission = 임무 / 파일럿 등급 Green·Regular·Veteran·Elite = 신참·정규·숙련·정예 / 'Mech Bay = 메크 격납고 / Briefing·Deployment = 브리핑/출격, Deploy = 출격 / Ready Area = 출격 대기 구역 / Begin Mission = 임무 개시. 용어집도 이에 맞춰 수정되어 있습니다.

## 1. 문자와 인코딩 (모든 텍스트 공통)

게임은 EUC-KR 바이트열을 그대로 그리고, 한글 폰트(Galmuri 기반 .FNT)에는 아래 글자만 들어 있습니다.

| 쓸 수 있음 | 쓰면 안 됨 (빈칸으로 그려지거나 깨짐) |
|---|---|
| ASCII 0x20-0x7E (영문, 숫자, `" ' - . , : ; ! ? ( ) / * < > %` 등) | 한자 (`中`, `重` 등: 글리프가 없어 빈칸) |
| KS X 1001 완성형 한글 2,350자 | 완성형에 없는 음절 (`똠`, `햏`, `힣`, `뷁`, `쌰` 등) |
| | 한글 자모 (`ㅋ`, `ㅠ`, `ㄱ`: A4행, 글리프 없음) |
| | 전각 문자 (`Ａ`, `，`, `（` 등 A3행), 유니코드 문장부호 (`…` `“ ”` `‘ ’` `–` `—`), 이모지 |
| | KS X 1001 기호 (`·` `※` `→` 등 A1/A2행): 폰트에는 있지만 쓰지 않습니다 |

* **주의:** 파이썬 `"...".encode("euc_kr")`는 errors="strict"여도 `똠`/`햏`에서 오류를 내지 않습니다. 대신 8바이트 조합형 시퀀스(`A4 D4 ...`)를 만들고, 게임은 이 시퀀스를 빈칸으로 그립니다. 그래서 "인코딩이 된다"만으로는 검사가 끝나지 않습니다. 한글 한 글자가 정확히 2바이트이고 첫 바이트가 0xB0-0xC8인지 확인해야 합니다. `check_glossary.py`와 `tools/build_strings_bin.py`가 이 방식으로 검사합니다.
* 문장부호는 ASCII만 씁니다. 큰따옴표 `"`, 작은따옴표 `'`, 줄임표 `...`, 대시 `-` 또는 `--`(원문 그대로)를 씁니다. 가운뎃점 대신 쉼표나 `/`를 씁니다. 물결표 `~`는 원문에 없으니 쓰지 않습니다.
* 한글 1자는 2바이트입니다. 바이트 제한(3.4절, 4.3절)은 이 기준으로 셉니다.

## 2. 공통 표기 원칙

### 2.1 음차 기준
* 고유명사는 음차합니다. 메크, 차량 이름, 조종사 이름/호출부호, 인물, 행성/지명, 세력, 작전명이 여기에 들어갑니다.
* 기준은 국립국어원 외래어 표기법입니다. 다만 사용자 지정 표기와 국내 배틀테크 커뮤니티(나무위키)에 정착한 표기가 먼저입니다. 예: 매드캣, 포트 아서, 예거메크, 코만도, 세르막, 다비온, 라이란 연방, 엘리멘탈, 옴니메크.
* 고유명사 안의 **유형어**는 번역합니다.
  * 지형: River 강, Bay 만, Valley 계곡, Basin 분지, Mountains 산맥, Mount ~ 산, Canyons 협곡, sector 구역, Base X는 X 기지
  * 조직: Company 중대, Guards 근위대, Dragoons 용기병대, Commonwealth 연방, Combine 연맹, Operation 작전
  * 예: `Serpent Bay` 서펀트 만, `Base Nomad` 노마드 기지, `Zulu Company` 줄루 중대, `First Davion Guards` 제1 다비온 근위대
  * 이름 전체가 하나의 고유명사인 것은 통째로 음차합니다. 예: `Inner Sphere` 이너 스피어, `Smoke Jaguar` 스모크 재규어, `Star League` 스타 리그, `Bandit Kingdoms` 밴딧 킹덤
* 같은 대상의 철자가 원문에서 흔들려도 한국어는 하나로 씁니다.
  * `Mad Cat`/`Madcat`은 매드캣, `Shadow Cat`/`Shadowcat`은 섀도캣, `Star League`/`Starleague`는 스타 리그, `OmniMech`/`Omnimech`은 옴니메크
  * `Re-Education`/`ReEducation`은 재교육, `Batallion`(원문 오타)은 대대, `Draonic Combine`(오타)은 드라코니스 연맹

### 2.4 계급과 호칭
* 이너 스피어 계급은 이름 **뒤**에 씁니다. 예: 네언 대위, 리스 대령, 피오트레프 소령, 아코도 하루 대위
* 클랜 계급은 음차해서 이름 **앞**에 씁니다. 예: 스타 캡틴 마커스 오시스, 스타 커널 마커스 코타레
* xbrf0103의 `Clan Captain Katherine Furey`도 스타 캡틴으로 씁니다(desc472 기준).
* `Cpt.`, `Capt.`는 줄이지 않고 "대위"라고 씁니다.

### 2.5 메크 이름 규칙
* EXE 문자열(700-771)은 `섀시 + 공백 + A/W/J`입니다. 예: `매드캣 A`, `헌치백 IIC J`
* 이름표 그림(LSCFLM*/LSPFLM*/LSPFDM*)은 `섀시-문자`입니다. 예: `매드캣-A`
* A = 장갑 강화형, W = 화력 강화형, J = 점프형입니다. 글자 자체는 라틴 대문자 그대로 둡니다(구매 화면의 A/W/J 버튼과 맞물려 있습니다).
* "Cat" 계열은 붙여 씁니다. 매드캣, 섀도캣, 노바캣
* 나머지는 원문 띄어쓰기를 따릅니다. 홀랜더 II, 헌치백 IIC, 폰 루크너
* 로마 숫자(II, IIC, IV)는 라틴 문자 그대로 둡니다.
* 소유격 `X's Y`는 `X의 Y`로 씁니다. 예: 퓨리의 벌처, 오시스의 마사카리
* 원문 `C ` 접두어(클랜제 부품)는 정식 이름에서 "클랜 "으로 쓰고, 약칭에서는 `C `를 그대로 둡니다. 예: `C Large ER Laser`는 클랜 대형 ER 레이저, 약칭 `C Lrg. ER Laser`는 C 대형ER레이저

### 2.6 경/중 표기
* 무기와 차량의 Light는 **경-**, Heavy는 **중(重)-**으로 붙여 씁니다. 예: 경오토캐논, 중오토캐논, 중화염방사기, 경전차, 중전차, 경호버 전차
* 라틴 약어 앞에서는 띄웁니다. 예: 경 LB-X 오토캐논
* Medium 차량은 "중형"입니다. 예: 중형 전차
* 무게 등급:
  * UI 공유 문자열은 경량 / 중간 / 중량 / 강습입니다(3.5절).
  * 문장 속에서는 경량급 / 중형급 / 중량급 / 강습급으로 씁니다. 예: `a Heavy 'Mech`는 중량급 메크, `assault-class OmniMech`는 강습급 옴니메크
* Large / Medium / Small(레이저, 점프젯)은 대형 / 중형 / 소형입니다.

### 2.7 숫자, 단위, 띄어쓰기
* 아라비아 숫자, 시간 형식(`15:00`), 소수점(`0.5`)은 원문 그대로 둡니다.
* 단위는 이렇게 씁니다.
  * 무게: `15 tons`는 15톤
  * 시간: `25 MINUTES`는 25분
  * 탄수: `(40 shots)`는 (40발)
  * 거리: `350 meters`는 350미터, `50m`은 50m
* 수 세는 말: 메크는 기, 차량은 대, 사람은 명, 건물과 지점은 곳/채, 그 밖은 개
  * 예: `three 'Mechs`는 메크 3기, `4 Supply Trucks`는 보급 트럭 4대
* 띄어쓰기는 한글 맞춤법을 따릅니다. 고유명사의 띄어쓰기는 용어집 `ko` 그대로입니다.
* 호출부호는 원문의 `Name`(Hawk)과 `Callsign`(HAWK)에 같은 한국어를 씁니다. 한글에는 대소문자가 없습니다.

## 3. UI 문자열 (strings.json, MECHTEXT.FIT, MECHREP.FIT, 임무 목표 이름, 그림 문구)

### 3.1 문체: 라벨은 명사, 문장은 "~합니다"체
* **라벨, 버튼, 표 머리글, 상태값**은 명사(구)로 씁니다. 마침표를 붙이지 않습니다.
  * 예: `Unit Cost`는 단가, `RP Remaining`은 잔여 RP, `Current Resource Points`는 현재 자원 포인트, `Dead`는 사망
* **문장형 텍스트**는 전부 "~합니다"체로 통일합니다. 툴팁, 도움말 줄, 안내, 경고, 확인 대화상자가 여기에 들어갑니다. 반말과 "~하십시오"는 쓰지 않습니다. 단, 사용자에게 무엇을 해 달라고 요청하는 문장은 "~해 주십시오"로 씁니다(1256 CD 요청).
* "Drag X into Y to Z." 형 툴팁은 "Y(으)로 끌어다 놓아 Z합니다."로 통일합니다.
  * 45 `Drag into Battalion Inventory to sell.`는 "대대 보급고로 끌어다 놓아 판매합니다."
  * 32 `Drag a unit here from the Ready Area.`는 "대기 구역에서 유닛을 이곳으로 끌어다 놓습니다."
  * 59 `Slide right to repair armor.`는 "오른쪽으로 밀어 장갑을 수리합니다."
* "View X." 형은 "X을/를 봅니다."입니다. 예: 41 "보유 중인 배틀메크를 봅니다."
* 질문은 "~하시겠습니까?"로 씁니다. 예: 116 "이 파일을 삭제하시겠습니까?", 117 "저장된 게임을 덮어쓰시겠습니까?"
* 결과 알림은 "~했습니다."로 씁니다. 예: 118 "게임을 저장했습니다."
* 오류는 "~할 수 없습니다."로 씁니다. 예: 77 "자원 포인트가 부족하여 이 품목을 구매할 수 없습니다."
* 원문 끝에 마침표나 콜론이 있으면 유지하고, 없으면 붙이지 않습니다. 84 `...could not be replaced:`처럼 끝이 콜론이면 한국어도 콜론으로 끝냅니다. 원문 끝 공백도 지키세요. 893 `Inventory: `는 "보유: "입니다.

### 3.2 printf 자리표시자
* `%s %i %d %f %.0f %.1f %03i %%`는 **개수, 순서, 철자를 그대로** 둡니다. 코드가 인자 순서를 고정하므로 어순 때문에 자리표시자 순서를 바꾸면 값이 뒤바뀌거나 게임이 죽습니다. 한국어 어순은 문장을 재구성해서 맞춥니다.
* 자리표시자 바로 뒤에 받침에 따라 달라지는 조사를 붙이지 않습니다(값을 모르기 때문입니다). 조사가 필요 없게 문장을 바꾸거나 "%d대" 같은 단위를 붙입니다.
* 예시:
  * 78 `%.0f Ton %s 'Mech`는 `%.0f톤 %s급 메크`입니다. %s에는 경량/중간/중량/강습이 들어가서 "75톤 중량급 메크"가 됩니다.
  * 83 `%.0f Ton %s Vehicle`는 `%.0f톤 %s급 차량`입니다.
  * 639 `%.1f tons`는 `%.1f톤`입니다.
  * 882는 `보유 중인 메크와 차량은 %d대이며 최대 %d대입니다. 유닛을 되팔지 않으면 앞으로의 노획품을 잃을 수 있습니다.`입니다. %d 두 개의 순서가 그대로 유지됩니다.
  * 887 `%s's game`(멀티플레이)은 `%s의 게임`입니다.
* `\n`(97, 153, 154, 1257)은 실제 줄바꿈입니다. 개수와 위치를 유지합니다.

### 3.3 임무 목표 이름 (MISSION.FST 임무 FIT의 `[ObjectiveN] Name`)
* 임무 중 목표 목록과 임무 결과 화면에 나옵니다. **UI이므로 명사형으로 끝냅니다.**
  * 예: `Capture 4 Supply Trucks`는 보급 트럭 4대 노획
  * 예: `Destroy Camp Alpha HQ and Natural Gas Tower`는 알파 수용소 HQ 및 천연가스탑 파괴
  * 브리핑 본문의 목표 줄은 같은 내용을 명령형으로 씁니다(4.1절).
* 동사는 이렇게 옮깁니다(`glossary.json` structures_objectives의 `Liberate` 항목 참고).

| 원문 | 한국어 | 원문 | 한국어 |
|---|---|---|---|
| Destroy | 파괴 | Escort | 호위 |
| Capture (건물, 기지) | 점령 | Rescue | 구출 |
| Capture (차량, 보급품, 메크) | 노획 | Eliminate / Take Out | 제거 |
| Defend | 방어 | Secure | 확보 |
| Protect | 보호 | Move / Get to | 이동 |
| Withdraw | 후퇴 | Seek & Destroy | 수색 섬멸 |

* 괄호 수량 `(2)`와 번호 `1`-`5`는 그대로 둡니다. 원문 오타(`Destory`, `Defense Allied ...`)는 뜻대로 옮깁니다.
* MIS0506의 `Placeholder`는 실제로 표시될 수 있습니다. 기본값은 "임시 목표"로 두고, 문구는 리드와 상의합니다.

### 3.4 길이와 버퍼 제한

## 4. 브리핑 (MISSION.FST `brf*.txt` 32개, `xbrf*.txt` 13개, `xsbrf*.txt` 3개)과 부품 설명 (desc.fit)

### 4.1 문체: 군사 전문(電文) 문체
* **제목** `***...***`은 명사형입니다. 예: `***노동 수용소 해방***`, `***스타베이스 점령***`
* **목표 줄** `1-...`은 명령형 "~하라"입니다. 예: `1-알파 수용소 HQ와 천연가스탑을 파괴하라`. 꼬리말 `(secondary)`는 `(부 목표)`로 씁니다.
* **본문 서술**은 문어체 평서 "~한다/~했다/~이다"입니다. 지시는 "~하라/~하지 마라", 권고는 "~할 것을 권한다"로 씁니다. 존댓말은 쓰지 않습니다.
  * 예: `Intelligence reports that ...`는 "정보부 보고에 따르면 ...", `Be advised that ...`는 "...에 유의하라.", `Good luck.`은 "행운을 빈다."
* **화자가 드러나는 전문**도 같은 해라체를 쓰되 말투를 조금 살립니다. 해당 파일은 brf0401 리스 대령의 서신, xbrf0304 `Here we go, team.`, xsbrf0401/0404 클랜 측 화자입니다. 플레이어 호칭은 계속 "지휘관"입니다. 예: `I'd say good luck but ...`는 "행운을 빈다고 하고 싶지만 ..."
* TACTICAL WARNING/NOTICE의 `*` 항목은 원문이 서술이면 평서, 지시면 명령으로 씁니다.
* **desc.fit**의 부품/메크 설명과 조종사 소개(desc301-350)는 문어체 평서 "~한다/~이다"입니다. 되풀이되는 문장은 `fixed_phrases`의 고정 번역을 씁니다. 예: "이 파생형은 장갑이 강화되었고 점프젯이 없다."

### 4.3 마크업(SMUTI) 규칙: 반드시 지킬 것
1. **모든 `%` 코드를 원문과 같은 순서, 같은 철자(대소문자 포함)로 둡니다.** 대상 코드는 `%n %c %fs %fm %fl %fc1-%fc8 %t9 %t12`입니다. 바꾸는 것은 코드 사이의 영어뿐입니다. 코드를 더하거나 빼지 않습니다. 하나만 예외로, 들여쓰기 줄이 너무 길 때는 원문과 같은 방식으로 `%n` + 원래 들여쓰기 코드(`%t9`/`%t12`)를 더해 줄을 나눌 수 있습니다.
2. **`%fc` 뒤 숫자는 한 자리**입니다. `%fc21-Destroy`는 `%fc2` + `1-Destroy`입니다. 번역해도 `%fc21-...`은 그대로입니다. 숫자를 지우거나 띄우면 색과 목표 번호가 함께 깨집니다.
3. **줄바꿈은 `%n`만** 됩니다. 파일 안의 CR/LF/TAB은 무시됩니다. 원문의 물리적 줄 구조(CRLF)를 그대로 따라 쓰면 원문과 비교하기 쉽습니다. 빈 줄은 `%n%n`입니다.
4. **파일의 마지막 2바이트는 버려집니다.** 파일은 반드시 CRLF로 끝나야 합니다. 그렇지 않으면 마지막 글자가 잘립니다. 원문 파일은 CRLF + ASCII이고, 번역본은 CRLF + EUC-KR로 저장합니다(UTF-8 금지, BOM 금지).
5. **자동 줄바꿈은 공백(0x20)에서만** 일어납니다. 한국어는 어절 사이에 공백이 있으니 보통 문단은 괜찮습니다. 공백 없는 긴 덩어리(50자 이상)는 만들지 마세요. 코드 사이 텍스트 버퍼가 256바이트라서 공백 없이 128자를 넘으면 넘칩니다.
6. **`%c` 가운데 정렬은 다음 `%` 코드까지 최대 80바이트(한글 40자)만** 잽니다. 그리고 한 줄만 정렬합니다. 패널 폭 때문에 실제로는 **소형 폰트 기준 한글 약 20자 이하**로 쓰세요. 긴 제목은 원문처럼 `%c...%n%c...` 두 줄로 나눕니다. 예: brf0104 `%c***DESTROY CLAN***%n%c***HEADQUARTERS BUILDING***`는 `%c***클랜 본부 건물***%n%c***파괴***`
7. **들여쓰기 줄**(`%t9`, `%t12`로 시작하는 목표, 화력 지원, 경고 항목)은 원문처럼 손으로 끊습니다. 원문에서 손으로 끊은 줄은 가장 넓은 것이 약 167px(소형 8px 폰트)입니다. 한글로는 **한 줄 20자(공백 포함 160px) 이하**입니다. 자동으로 줄이 바뀌면 다음 줄이 들여쓰기 없이 맨 왼쪽에서 시작합니다.
8. **리터럴 `%`**: `%` 뒤에 한글이나 영문자가 오면 코드로 오인될 수 있습니다. `50%를`처럼 쓰지 말고 `50% 감소`(뒤에 공백)나 `50퍼센트`로 씁니다. brf0103 `by 50% `가 그 예입니다.
9. 백틱과 작은따옴표(`` `Mechs ``, `'Mech`)는 한국어 "메크"에서 지웁니다. 큰따옴표 `"Alpha"`는 ASCII로 남깁니다. 예: `"알파"`
10. 원문의 대문자 강조(`ULLER`, `CATAPULT`, `HUNCHBACK IICs`)는 한글에 대소문자가 없으니 그냥 음차합니다(울러, 캐터펄트).
11. 원문 오타(`insure`, `suprise`, `moral blow`, `of of`, `there is not have much time`)는 뜻대로 옮깁니다.

## 6. 검수 체크리스트
1. `python -I localization/ko/check_glossary.py`가 오류 0으로 끝나야 합니다.
2. 용어집 용어를 그대로 썼는지 확인합니다(특히 메크/차량/부품 이름, 계급 위치, 무게 등급).
3. EUC-KR 검사를 합니다. 한글은 전부 2바이트이고 첫 바이트가 B0-C8이어야 하며, 한자, 자모, 전각 문자가 없어야 합니다.
4. 원문과 번역문의 자리표시자 목록과 `%` 코드 목록이 같아야 합니다. 대소문자는 구분하지 않고 비교합니다.
   ```python
   import re
   CODES = re.compile(r"%(?:fc\d|f[sml]|t\d+|[cn%])", re.I)
   PRINTF = re.compile(r"%[-+ #0]*\d*(?:\.\d+)?[sdif]")
   assert [c.lower() for c in CODES.findall(src)] == [c.lower() for c in CODES.findall(dst)]  # 브리핑과 desc
   assert PRINTF.findall(src) == PRINTF.findall(dst)                                          # strings.json
   ```
   들여쓰기 줄을 나누려고 `%n%t9`를 더한 경우는 그 차이만 있어야 합니다.
5. 바이트 제한을 확인합니다. 79-82와 100-102는 14바이트 이하, `%c` 구간은 80바이트 이하입니다. 브리핑 파일은 CRLF로 끝나야 합니다.
6. 화면에서 확인합니다. 들여쓰기 줄이 자동으로 줄바꿈되지 않았는지, 가운데 정렬 제목이 한 줄인지 봅니다.
