# localization/

English source texts of MechCommander Gold / Expansion (MCX.EXE 1999) that a translation has to cover.
Everything here is generated by `tools/extract_text.py` (see below) and is **read-only extraction**: no game
file is modified.  `localization/en/` is the English baseline; a translation would live next to it
(`localization/ko/` ...).

## Layout

```
localization/
  README.md                this file
  en/
    strings.json           all 835 EXE string-table entries (id, text, callers, screens, scope, kind, placeholders)
    strings_summary.md     counts per scope + table of the pre-mission strings + notes on how the engine loads them
    dialogs.json           the 6 Win32 DIALOG resources of the EXE (crash dialog, DirectPlay dialogs)
    hardcoded_strings.json English prose that is compiled into the code instead of the string table (14 entries)
    briefings.json         the 129 briefing .txt files: size, referencing mission FIT, campaign, markup codes used
    markup.md              every `%` code of the briefing / description markup (SMUTI) with counts and meaning
    fit_strings.json       player-facing `st` strings of FIT/CSV data files {file, section, key, text, category, scope}
    fit_strings_summary.md per-file counts + notes on ambiguous sources
    art.json               every TGA of ART.FST (+ TERRAIN.FST): size, bpp, has_text, text_guess, used_by, contact sheet
    art/                   contact sheets (PNG) + review.json (hand-written verdicts, input of art.json)
tools/
  extract_text.py          driver:  python tools/extract_text.py [all|strings|briefings|fit|art] [--no-sheets]
  loc_common.py            paths + small helpers          loc_fst.py   FST archive reader (LZ via mcg_pkk.py)
  loc_strings.py           EXE string table + cLoadString call-site analysis (capstone)
  loc_briefings.py         briefing inventory + markup.md      loc_fit.py   FIT/CSV strings      loc_art.py   art inventory + sheets
```

Rerun: `pip install capstone pillow`, then `python tools/extract_text.py` (under a minute).  Inputs: the extracted folders
in the repo (`MISSION.FST/`, `MISC.FST/`, `ART.FST/`, `data/objects/OBJECT2.PAK/`) and the git-ignored local install
`game-source/extracted/MCX/` (`MCX.EXE`, `ART.FST`, `TERRAIN.FST`; symbol map `game-source/extracted/rea-test/mcx_symbols.json`).
If capstone is not importable set `MCG_CAPSTONE_PATH` to a folder that contains it.

## How each file was produced

* **strings.json** - the STRINGTABLE resource of MCX.EXE is parsed from the PE (835 strings, ids 1..1257, LANGID 1033).
  All 229 `call cLoadString` (VA 0x75aa30) sites are found by scanning .text; the id is the second argument pushed
  (`push size; push buf; push id; push hInst`).  The enclosing function comes from the symbol map and is mapped to a screen by
  name (BriefingScreen, PurchaseScreen, RepairScreen, *InventoryBlock, MissionResultsScreen, SessionScreen/LAN/Modem = multiplayer,
  TacticalMap/InterfaceObject = in-mission, aSystem::start = system ...).  Several call sites are shared tails reached by
  jumps, so the id search walks backwards through jump targets.  Register ids are resolved from data (mech names = FIT
  `DescIndex`+300, vehicles +700, objects = `BuildingName` in OBJECT2.PAK).  `scope` is the strongest scope among the callers
  (pre-mission > multiplayer > system > in-mission); `also_scopes` lists the others.  `kind` separates real UI text from
  printf templates (`format`) and identifiers that must not be translated (`identifier`, `debug`).  Ids without any reference
  keep `referenced: false` (+ `guess_scope`).
* **briefings.json / markup.md** - every `*.txt` of MISSION.FST; the referencing mission FIT comes from
  `st BriefingFile / ISBriefingFile / ClanBriefingFile`; the markup was decoded from `SMUTI::process` (VA 0x728ed0) and
  counted over the files.
* **fit_strings.json** - `st Key = "text"` lines of the objective sections of all mission FITs, pilot / crew / mech / vehicle
  profiles, `desc.fit`, `MECHTEXT.FIT`, `MECHREP.FIT`, `Menus.fit` and the name/abbr columns of `compbas.csv`; identifiers (file
  names, art, brains, palettes, profiles) are excluded.
* **art.json / art/** - the TGA entries of the *game's* ART.FST are decompressed in memory (LZ stream per entry), decoded with Pillow
  and tiled into contact sheets.  `has_text` / `text_guess` come from looking at the sheets and are stored in `art/review.json`
  (rules by name pattern + exact file verdicts); anything not covered stays `"unsure"` (2 files).  `used_by_screen_fit` comes from
  the `//` comments of the ART.FST screen FITs, `used_by_code` from the TGA name patterns embedded in the EXE.

## Things you may not expect

1. **The repo's `ART.FST/` folder is incomplete**: it has the 622 top-level files (483 TGA) but not the `data\art\logart\` sub-tree
   (915 TGA, 1029 entries) that the real archive contains.  All logistics screens (briefing, mech bay, purchase, repair) draw their
   panels and labels from `logart`.  `art.json` therefore reads the TGAs from the local game install's ART.FST (1398 TGA); TERRAIN.FST
   (147 map TGA) is included as well.
2. **Text is baked into the art far beyond the buttons**: besides the 150+ button TGAs there are name plates with the mech / vehicle /
   component / pilot names (`LSCFLM*`, `LSPFLM*`, `LSPFDM*`, `LSCFLV*`, `LSPFLV*`, `LSPFDV*`, `LSPFLC*`, `LSPFDC*`, `LSPFLP*`: 469 files),
   panel backgrounds with all field labels (`LSBBK00`, `LSPBK00`, `LSRBK00`, `Ses_bk00`, `mr_bkgd`, `MM_WN01/02`, `PREFS_00` ...), the operation
   title cards (`LSB_OP*`, `MCXCard*`), vertical tab strips and the font glyph sheets.  The mech/pilot/vehicle names exist *twice*:
   in the EXE string table and in these plates.
3. **`languageOffset`**: every string id is offset by `Language` from `SYSTEM.CFG` (see `strings_summary.md`); the engine was built
   for several languages in one string table.
4. The briefing renderer SMUTI drops the last two bytes of each file, ignores real line breaks, wraps at 0x20 only and works byte by
   byte (see `markup.md`).
5. 355 of the 835 string ids are never referenced (spare building names, a block of mission-report strings 1-28, section headings 88-94 ...).
6. A few UI strings are compiled into the code (`hardcoded_strings.json`), e.g. the format `%.0f Ton %s 'Mech` exists as a literal as well as string 78.
7. ABL scripts hold only debug strings; `radio.csv` has only message ids (the speech is audio); movies (`DATA/MOVIES/*.SMK`) and sound are not text.
8. `desc.fit` component descriptions (217) are the biggest block of free text that is shown before a mission; they use the markup and
   still contain "IF YOU SEE THIS DESCRIPTION PLEASE REPORT IT AS A BUG" placeholders.

## Building the Korean overlay (`tools/build_korean_overlay.py`)

Turns the UTF-8 translation sources in `localization/ko/` into the files the patched `MCX.EXE` reads in Korean mode
(prefs `l Language=1`): `game-source/extracted/MCX/lang/kor/` (EUC-KR, CRLF; only files that differ from the originals are
needed, the game falls back to the originals for everything else).

```
python -I tools/build_korean_overlay.py [--game-dir DIR] [--repo DIR] [--out DIR] [--only strings|briefings|fit|pilots]
                                        [--check] [--strict] [--warrior-fits] [--roster-dir DIR] [-v]
python -I tools/test_build_korean_overlay.py        # unit tests (fixtures in a temp dir)
```

| source | written to `lang\kor\` | notes |
|---|---|---|
| `ko/strings.json` `{"31": "..."}` | `strings.bin` | built with `tools/build_strings_bin.py` (same strict KS X 1001 check; 255-byte and printf-placeholder warnings) |
| `ko/briefings/<name>.txt` (UTF-8) | `data\missions\<name>.txt` | EUC-KR + CRLF, ends with CRLF (the engine drops the last 2 bytes). Warns when a `%` markup code count differs from the English file (`%tN` is counted by kind, not by N) or a line is over 253 bytes; **fails** when a `%c` segment is over 80 bytes |
| `ko/fit_strings.json` `[{file, section, key, en, ko}]` | the file's own path inside the game FST (`data\missions\`, `...\warriors\`, `...\profiles\`, `data\objects\desc.fit`, `data\objects\compbas.csv`, `data\objects\MECHTEXT.FIT`, `data\iface\Menus.fit`, `data\iface\MECHREP.FIT`) | copy of the original with only the matching `st Key = "..."` value (or `compbas.csv` name/abbr cell) replaced, everything else byte-identical. Entries with an empty `ko` are skipped; an unknown section/key is an error; a differing `en` only warns. `compbas.csv` rows whose abbr was identical to the name follow the translated name |
| `ko/pilots.json` `{"Hawk": {"name", "callsign", ...}}` | `data\savegame\START0.PKK`, `XSTART0.PKK` | the installed rosters (`DATA\SAVEGAME\`, or `--roster-dir`) with `st Name` / `st Callsign` of the warrior packets replaced; RAW packets + checksum header, re-read and compared. `callsign_en` / `alt_callsigns` select the callsign per English callsign. `--warrior-fits` also writes Korean copies of the `data\missions\warriors\*.fit` whose Name is in `pilots.json` (files that `fit_strings.json` translates win) |

Missing sources are skipped with a note.  Every text is encoded strictly as KS X 1001 (a syllable outside the 2350 set,
e.g. the jamo sequences Python's `euc_kr` codec silently emits, is an error; symbols/jamo outside the syllable rows warn).
Files with an error are not written and the exit status is 1; `--check` validates without writing; `--strict` turns
warnings into errors.  The output is deterministic and unchanged files are not rewritten.  The tool never writes below
`lang\kor\data\art\` or `lang\kor\data\fonts\` (other tools own them).  Original files are taken from the extracted
`MISSION.FST/` / `MISC.FST/` folders of this repo, the in-game paths from the FST headers of `--game-dir`.
